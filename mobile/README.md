# 相悦 · 原生 App（React Native / Expo）

同一套后端（`../server`）的原生客户端，iOS 与 Android 共用一份代码。

## 怎么在手机上跑起来

```bash
git pull                     # 先拿最新的（比如这份文档的修正）
cd mutual-app/mobile
npm install
npx expo start               # ← 不要加 --tunnel
```

手机上装 **Expo Go**（App Store / 应用商店搜得到），扫终端里出现的二维码。
**手机要和电脑在同一个 Wi-Fi 下**，走局域网直连最快，改代码保存后手机会自动刷新。

> ⚠️ **别加 `--tunnel`**：隧道是给「开发机在云上、手机连不到它」的场景用的，
> 多绕一跳公网，慢且容易断（表现为手机上提示 `Cannot connect to Expo CLI`，
> 因为手机连不上 `*.exp.direct`）。本机开发用局域网直连即可。
> 只有当手机和电脑确实不在同一网络（例如手机用流量）时才需要隧道，
> 且首次会提示安装 `@expo/ngrok`。
>
> 局域网也连不上时按这个顺序查：① 手机与电脑是否同一 Wi-Fi（不是访客网络）；
> ② macOS 防火墙是否拦了 node（系统设置 → 网络 → 防火墙，首次运行会弹窗询问，
> 要点「允许」）；③ 重启 `npx expo start`。

打包上架时再走 EAS（`npx eas build`），那时才需要 Expo 账号与证书。

## 接口地址

默认指向线上：`https://mutual.jianjiange.site/api/v1`（见 `src/lib/api.ts`）。
本地起后端调试时用环境变量覆盖：

```bash
EXPO_PUBLIC_API_BASE=http://<你的局域网IP>:8099/api/v1 npx expo start
```

## 与 Web 版的关系

- **同一套设计令牌**：色值、圆角、阴影在 `src/theme/index.ts` 与
  `web/tailwind.config.ts` 里必须一致，改配色两边一起改。
- **同一套交互语言**：点一行 → 底部弹层 → 选完收起；长列表用滚轮而不是输入框。
- **划卡：滑动与按钮并存**。右滑喜欢、左滑跳过，同时保留底部按钮——按钮是
  无障碍的兜底（非顶层卡对屏幕阅读器是隐藏的，只有按钮可用）。两条路径走同一个
  `act()`，不做两套状态机。（早先"只用按钮"的产品约束已被推翻，见 git 历史。）

## 资料向导（五步）

`app/onboarding.tsx` + `src/onboarding/`（纯逻辑）+ `src/components/pickers/`（选择器）。

- **每点一次「下一步」就先存服务端，存成功才翻页**。因此填到一半退出能续上：
  下次进来用 `/users/me` 回填（那一组路由刻意没挂 OnboardGuard）。
- **生日也回填**（2026-10-11 修的）：服务端只对**本人**下发 `birthday`（`YYYY-MM-DD`），
  别人视角仍然只有 `age`（PRD 15 章的隐私口径）。⚠️ 之前是所有人都不给，症状是
  **编辑资料时生日不回显、每次都要重选**——手一滑就把生日改错了。解析失败就让它空着，
  **绝不能拿 age 编一个**。
- **判定与请求体抽在 `src/onboarding/draft.ts`**：这一屏全是原生选择器（滚轮、
  底部弹层、系统相册），jest 里渲染不出真实交互，逻辑留在页面里等于零覆盖。
- **弹层的拖拽手势只挂在把手和标题栏上**（见 `ui/sheet.tsx`）：挂在整块面板上会
  和里面的滚轮/列表抢纵向手势，RNGH 默认优先级更高，里面就滚不动了。
- **地区（家乡 / 现居地）＝底部弹窗 + 省市联动的两列选择**（`region-sheet.tsx`）：
  左边省、右边该省的市，**点省当场换右列**；现居地再往右列里钻一层到区县（顶上一条
  「‹ 杭州市」退回市列表）。上一版是省/市/区三屏平铺——看不到自己在哪一级，改一个
  已填的市要从头点三下。搜索保留（「杭州」「hangzhou」「hz」），而且**搜到市之后不直接
  收口**，会落进联动列表里，让人还能改主意挑区县。
  ⚠️ **key 与"哪个省选中"都按名字比，不按 `code`**：港澳台在统计局数据里没有 code
  （空串），拿 code 比会一次点亮好几个省。
- **院校只留"输入即搜"一个入口**（`list-sheets.tsx`）：曾经铺过一排"按省份找"的标签，
  但那是一次多余的跳转——想找浙大的人会直接打「浙大 / zj」，不会先想"它在浙江"；
  省名仍然能当关键词搜到。职业、多选那两个仍是标签网格 + 搜索。
- 与 Web 版的差异：「期望身高」用双滚轮（Web 是双滑块，`gap=5` 的语义保留）；
  院校结果上限 30 条。
- **MBTI 和 Web 同思路：按四个维度各答一次，不铺 16 个类型**（`components/pickers/mbti-sheet.tsx`
  + `lib/mbti.ts`）。区别只在操作方式——Web 是四根 `range` 滑杆，App 是三段式点击
  （左字母 / 未选 / 右字母）：底部弹层里的横向拖拽会和面板的拖拽手势抢，
  而手感类问题本机没有真机可验，所以不冒险。四个维度答完才出现「确认」，落库值不变。

## 对某个人的操作（举报 / 拉黑 / 解除配对）

都在**对方主页右上角的「⋯」**里（`src/components/user-actions.tsx`）。放这一页而不是
聊天室，是因为它本来就是"和这个人的关系动作"的唯一去处；聊天室标题栏点一下也能到。

- 三个动作都走原生 `Alert` 二次确认——它们都不好撤回。
- ⚠️ 后端语义（别凭直觉改文案，见 `server/internal/service/action.go`）：
  `Block` 幂等，会让匹配变 blocked、会话变 frozen；`Unmatch` 只把会话转**只读**；
  `Unblock` **只删黑名单行，不恢复匹配和会话**——所以拉黑文案如实写"配对无法恢复"。
- 拉黑是**双向阻断**的：之后自己再点进对方主页也会被挡（`PublicProfile` 里
  `isBlocked` 命中即报错），页面会显示服务端给的原话。
- 解配需要 `matchId`，而对方主页只带回 `relation.matched`，所以点解配时会按需查一次
  `GET /matches` 再按 userId 找回来。

## 「加我微信提建议」入口

两个落点（`src/components/support.tsx`）：

1. **注册完成后自动弹一次**（`app/onboarding.tsx` 第一屏，本机记一个"看过了"的标记）；
2. **「我的」页常驻一行**——真正的反馈发生在用的过程中（"这里怎么点不动"），
   那时用户不会回到注册那一屏。

⚠️ **刻意不放登录/注册页**（用户 2026-10-11 定的）：那两页不需要登录也能看，
但用户的意思是"先让他进来再说"——注册卡住的人暂时找不到我们，是已知的取舍，别再提这茬。

微信号**由服务端给**（`GET /support`，见 `server/internal/config` 的 `SupportWechat`）：
联系方式会变，写死在客户端就得重新发版。**没配就整个入口都不显示**——宁可没有，
也别摆一个假的微信号。改法：`config.go` 里那一行默认值（或给部署加 `SUPPORT_WECHAT` 环境变量）。

弹层里是一键复制（`expo-clipboard`）+ 微信号大字可选中，`__tests__/support.test.tsx` 钉着复制这条链路。

## 账号被封禁时的表现

口径：**封禁 = 限制互动，不是把人踢出去**（用户 2026-10-11 明确）。

- 被限制的人**照样能登录、能刷推荐、能看消息、能改资料**——但**不能操作**：
  「划卡」（喜欢**和跳过**）与「发消息」都被拦（服务端 `service.checkRestricted`，
  由 ActionService / ChatService 调用；**拦截点不在中间件**——装回中间件的表现是
  "连推荐页都打不开"）。
  ⚠️ 一开始只拦了 like、把跳过留着，被用户否掉（"还是可以左滑右滑"）：**被限制就不该能划卡**。
- 客户端也拦住：推荐页对被限制的账号**不挂横滑手势**、两个按钮变暗且按下去只弹原因
  （**不做 disabled**——disabled 的按钮点下去毫无反应，用户会以为 App 坏了），
  那条「左滑跳过 · 右滑喜欢」的提示也不显示（它是个假承诺）。
- 客户端表现是一条**横幅**（`src/components/restriction.tsx`，挂在推荐页与消息页顶部）：
  点开能看到管理员填的原因原话、"还有哪些能用"、以及「联系客服」（配了微信号就直接开客服弹层）。
  点到被拦的动作时，服务端那句话（"账号被限制：暂时不能喜欢别人"）直接弹 toast。
- 限制状态放在 auth store：启动时从 `/users/me` 的 `accountStatus` + `banReason` 读，
  被拦的动作会再刷一次拿最新原因。
- ⚠️ 上一版是**整屏遮罩**（把人整个盖住 + 登录也进不来），和"不是踢"正好相反，别改回去。
- 别人那边：被封的人不出现在别人的推荐/广场里，主页和相册（含头像）不可访问——
  封禁的由头通常就是"资料或相册有问题"，那些内容不该继续被看到。

## 服务端错误码的一个约定（踩过）

`handler.mapErr` 只认识**哨兵错误**和 `InvalidInputError`，其余一律兜底成
500「服务暂时不可用」并把原消息丢掉。所以 service 层凡是"写给用户看"的错误，
都必须用哨兵或 `invalidInput(...)`——**裸 `errors.New` 会把确定的状态说成服务故障**。
真实踩过两处：拉黑后看对方资料、被封禁的账号登录。

两道测试钉着它：`server/internal/handler/response_test.go`（映射对不对）和
`server/internal/service/user_actions_test.go`（service 真的返回了哨兵没有）。

## 推荐卡：照片铺满 + 信息压在下缘（2026-10-10 再改）

**照片铺满整张卡**（填满 stage 的可用区域），信息（名字/年龄、身高城市学历职业、
契合点 N + 几个标签、自述两行）压在照片下缘的渐层上。喜欢/跳过**浮在卡片上**
（左跳过、右喜欢，和滑动方向一一对应），页面不再有独立的底部按钮栏。

⚠️ 试过两版都被否掉，别回头：
1. **"上面照片 54% + 下面一块白底信息区"**——看着像图文长条，不像一张能划的卡，
   照片也不当主角了。
2. **卡片贴屏幕边**（stage 边距 0）——圆角正落在屏幕边缘，看着像整屏贴了一张图
   （用户原话："卡片的两边边框没有一点边距 很丑"）。"卡片全屏展示"指的是**卡片要大**，
   不是**卡片要贴边**。

⚠️ **推荐卡上不出现"部分条件不符"**：划卡那一刻要回答的是"要不要喜欢"，在这个位置
讲"哪里不合适"是反向劝退。**对方主页（`profile-card.tsx`）那条保留**——PRD 7.2 要求
软条件不符如实告知，那一页才是看细节的地方。

为什么值得占这么大地方：只看一张脸就左滑右滑，用户其实是在盲选。把契合点摆出来
（而且是**真算出来的**，不是文案），一次划卡才是有依据的决定。
改之前这张卡只说了"她是谁"，没回答"为什么是她"。

数据来自服务端（`Card.reasons` / `sharedHobbies` / `aboutMe`）：
`forwardScore` 本来就在逐项算命中与未命中，现在把**命中的那一半也带出来**；
共同兴趣是新加的一个纯函数 `sharedHobbies`。

⚠️ **卡片手势别加 `failOffsetY`**：横向滑动时手腕带弧线，纵向很容易先超过十几像素，
那样手势会直接判负——症状是"左滑有时候划不过去"（踩过一次）。现在只要横向动 8px 就认，
纵向位移一律忽略。信息区也因此**不做滚动**，超长一律截断。

⚠️ 浮在卡上的按钮要放在**手势之外**（页面里渲染、不进 GestureDetector）：
普通 Pressable 塞进卡片里，点一下会同时触发"按钮"和"点开资料"。
而且按钮那一行铺满整宽，必须 `pointerEvents="box-none"`，否则它就吃掉卡片下半部分的触摸。

⚠️ 版面借鉴自主流推荐页，但**配色没有照搬**——借的是结构，视觉仍是本项目的
深酒红 + 象牙白 + 香槟金。

## 划卡页的版面（2026-10-10 重排）

参照主流划卡页（Tinder / Bumble / 探探）的共同做法：**照片是主角，chrome 极少**。
原来的问题是卡片偏小、下面一条空白带、按钮偏小且飘着——三点都反着来。

- **左右边距**：20 → 12 → 0 → **回到 12**。试过 0（卡片铺满整屏），很难看——圆角贴在
  屏幕边上就不像一张卡了。12 是这一屏的定稿值（主流划卡页 8–16）。
- **提示不再占布局**：原来是"卡片 → 8pt → 提示行 24pt → 16pt → 按钮"，
  这 48pt 是**常驻**的，提示消失后就成了卡片下面一条永远空着的带子。
  现在提示是个**胶囊浮在按钮上方**（`position: absolute`），不挤压任何一侧；
  它本来就只在第一次划卡前出现。
- **按钮加大**（跳过 56→58、喜欢 64→72）并收紧行距，让底部像个"控件区"而不是
  两个飘在空白里的圆。
- **额度提示改成只在 ≤3 时才出现**（与「心动」页一致）：常驻一个
  「今日还可喜欢 N 人」会把划卡页变成记账本，这是"不够高级"的一个来源。
- 卡片姓名 21 → 23：名字要像标题，不是说明文字。

⚠️ 改 stage 的左右边距时记得同步 `cardW`——滑动阈值是按卡片宽度的比例算的
（现在是左右各 12，所以 `cardW = 屏宽 - 24`）。

⚠️ 浮在卡上的按钮浮层**必须显式写 `zIndex`**（Android 再补一个 `elevation`）：卡片自己带
`zIndex: 10`、飞出去那张 20，同级元素不写 zIndex 就按 0 算 ⇒ 照片整块盖住按钮。
症状是用户说的"可以点击的按钮也没了"。这类 bug 渲染测试抓不到（元素在、a11y 也在），
所以用 testID（`deck-stage` / `card-actions`）+ 样式值断言钉住。

## 推荐卡上的三种操作

最上面那张卡同时挂 **Pan（左右滑）** 和 **Tap（点开对方主页）**，用 `Gesture.Race`
组合：谁先成立谁生效——手指移动超过阈值时 Pan 先激活（Tap 随之取消），原地抬手
才是 Tap。**不用 `Exclusive`**：它让 Pan 有绝对优先权，而 Pan 在"没移动"时要等
手指抬起才失败，Tap 会白白多等一拍。

⚠️ 点开主页会（由服务端 `PublicProfile` 自动）记一条 `visit` 动作，而卡池的
`NOT EXISTS` **不区分动作类型**——所以**只是看过、没做决定的人，下次重新取卡时也会
消失**。当前会话内不受影响（这一页不用 `useFocusEffect`，回来时不重拉），Web 端行为相同。

### 现在的形态：**字标**（2026-10-11 换的）

用户给了一张参考（"良配"：一块深色圆角方块 + 白色粗体中文 + 角上一颗小星光），
要"没啥图形、就是很高级"。前两版几何图形都被评过"土"，做减法做到尽头，就是把图形去掉——
**让字本身当图形**。所以现在是一块底色 + "相悦"两个字 + 右上角一颗凹边四角星光，没有别的。

三个配色（`-design` 切换）：`wordmark-ink`（墨底象牙白字，**默认**，最贴参考）、
`wordmark-ivory`（象牙白底酒红字）、`wordmark-wine`（酒红底象牙白字）。
旧的几何方案（`rings-*` / `split-*`）仍在 `designs` 里可以跑出来，但不再是默认。

### 字形是从字体里抽出来的轮廓

两个字来自 **Noto Sans SC 900Black**，但**没有把字体放进仓库**（一个字重 10.5MB，
为了两个汉字不值当）：`tools/extract-glyphs` 把 相(U+76F8) / 悦(U+60A6) 的矢量轮廓导成
`glyphs.go`（字体单位整数，y 向下，约 2.8KB），图标按它栅格化、`logo.svg` 直接用同一份
path——**两边同源**，构建机上也不需要装任何字体。

要重新抽（换字体/换字）：

```bash
npm pack @expo-google-fonts/noto-sans-sc@0.4.4 && tar xzf noto-sans-sc-*.tgz
cd mobile/scripts/gen-icons/tools/extract-glyphs
go run . /path/to/package/900Black/NotoSansSC_900Black.ttf > ../../glyphs.go
```

字体是 OFL 1.1，随仓库分发轮廓没有问题（`glyphs.go` 头部写明了出处）。

排版参数在 `wordmark.go`：字间距 `wordGap=60`（0.06em，汉字自带字面，再近就糊成一块）、
星光半径 `sparkleR=104`、凹度 `sparkleK=0.26`、星光探出"悦"右沿 `sparkleCX=26`。
占画布的比例 `kindWordmark`：icon 0.62 / adaptive 0.52 / favicon 0.78 / mark 0.98
（比几何图形大一点——横长条视觉重量小）。

`-check` 除了原有的几何断言，还钉了字标这四条：**轮廓朝向**（y 向下时 CJK 字的墨迹上沿
必须是负数，抽错方向会整张图上下颠倒而覆盖率照样正常）、墨迹密度区间（20–65%；这个字重
实测 54.7%，防的是"字腔被填实"和"几乎没画上"）、左右两个字都有墨、星光落在最右侧。

### ⚠️ 两个还没处理的点

- `splash-icon.png` / `mark.png` 是**透明底 + 主题的 mark 色**。墨底主题下它们就是浅色字，
  只能压在深色底上；要用在浅色底（比如启动画面）得反过来取色。
- `favicon.png` 只有 48px，"相悦"两个字在那里已经很挤（认得出但发糊）。要更清楚的话，
  小尺寸应该改成**单个"悦"字**——需要在排版里加一个"单字"模式。

### 历史：为什么是"减法"，这些结论别丢

- **金 + 酒红是中文语境里"喜庆"的头号配色公式**（红包、婚宴、酒楼）。第二版还把金做成
  金属渐变，等于把那个信号又放大一层。**这一版没有金。**
- 渐变、暗角、拟物金属都是"想显得贵"的**加法**——但贵是减法。
- 两个等大正圆居中对称是图标库素材的形；图形占比 0.70、留白不足。

旧的两套几何形体（仍在选项里，参数也留着）：

- **双环相扣**：`kOverlap = 0.72`。这个常数是分水岭——0.5 左右是维恩图（两个集合），
  0.72 才是链环（相扣）。
- **分割的圆**：一个圆，中间一道正弦细缝。缝的**两端收到 0**（圆顶圆底仍连着）——
  完全切开会读成"两片"（是分开），连着才读成"整体的合缝"（是合）。

⚠️ **为什么是代码不是设计文件**：这台构建机跑不了任何图形软件（内核 3.10 + glibc 2.17，
Chromium / ImageMagick / rsvg / Python 图形库全装不上），但 Go 的 stdlib 能直接写 PNG。
好处是几何确定——改参数重跑即可，不会出现"某个尺寸忘了重新导出"。
**"画对了"和"好不好看"是两个问题，必须分开验**：前者交给 `-check`，后者只能靠对照图交给人。

⚠️ 对照图里 android 圆形遮罩那段曾经**从来没画出来过**：圆心用了绝对坐标去减相对像素
（`px-cx`，而 cx 是绝对坐标），标签在、圆不在，直到这次重排对照图才看见。现在按相对像素算。

⚠️ `splash-icon.png` 还没接上 `expo-splash-screen`（本项目没装这个依赖，装它需要联网）。

## 广场的分页与筛选

- 查询串交给 `src/lib/plaza.ts` 的 `plazaQuery()`——**数组按逗号拼、空数组整个不传**
  （服务端对空串是不加这条 SQL 的，传 `provinces=` 会让两头理解不一致）。
  这条有单测：拼错参数不会报错，只会安静地少筛一批人。
- 分页是 **keyset 游标**（`nextCursor`，0 = 到底），不是 OFFSET。用「加载更多」
  按钮而不是 `onEndReached`：游标归零时按钮消失，用户能看出没有了；自动续会在
  快速滑动时连着打好几页。
- 筛选弹层里的内容**可滚动**（`maxHeight` 62% 屏高）。
- **省份不在主面板里平铺**：主面板只留一行「地区  不限／浙江、江苏」，点进去换成
  第二屏——搜索框 + **按大区归组**（华北/东北/华东/华中/华南/西南/西北/港澳台）。
  34 个省份平铺要用户从头扫到尾，而且看不出地理结构；分组之后先落到一片、再找省，
  一次扫视就够。两屏是同一个 `Sheet` 换内容，**不是叠两个弹层**——两个 Modal 叠着
  既有遮罩加重的问题，返回也不自然。
- 大区分组是手写的，省份名单是自动生成的：`__tests__/provinces.test.ts` 直接和
  `PROVINCE_NAMES` 对，**不重不漏、顺序也要一致**（写错一个字，筛选就会"生效了但一个人都没有"）。

## 验证手段

- `npm run typecheck` —— 类型检查
- `npm test` —— 渲染冒烟测试（把每个页面真的渲染一遍，抓渲染期崩溃）+ 选择器交互测试
  （`__tests__/pickers.test.tsx`：省市联动、区县钻取、直辖市、搜索、院校）
- `npx expo export --platform android` —— 真打包，验证能出可上机的 bundle
- `npx expo-doctor` —— 依赖健康（版本是否与 SDK 匹配）

⚠️ **jest 跑在 CJS 里，原生 `import()` 会直接报** `A dynamic import callback was invoked
without --experimental-vm-modules`。受影响的是**懒加载的数据**（地名 215KB、院校名单）：
加载失败被 catch 吞掉后列表就是空的，症状很像"组件写错了"。已在 `babel.config.js` 里
按环境挂 `dynamic-import-node`（**只作用于 test**，打包时仍是真正的动态 import、会切 chunk）。
